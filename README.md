# 活记 — 个人 AI 智能体

> 一个人，24,000 行代码，250+ 源文件，18 岁独立完成的全栈作品。
> 你记录生活，它让数据活起来。

---

## 项目概述

### 为什么做这个产品

2026 年 6 月，父亲和工友常因"记工"扯皮——谁干了几天、借了多少钱，全靠口头记忆。我对 6 大方向做了市场扫描后发现：**"AI 语音记工 + 个人数据资产"全市场空白**——市面上的记账工具都要手动选模板、填字段，没有一款是"张嘴就记、AI 自动结构化"的。

于是有了活记：**不预设任何模板**。用户说一句话，AI 解析、自动分类、提取人物/金额/日期/状态，生成一张确认卡片。建筑工人记工、白领记会议、学生记笔记——用户决定记什么，AI 决定怎么结构化。

### 一句话定义

> 活记是一个**个人 AI 智能体**——你负责记录，它负责让数据变活。
> 存进去的是你说的话、拍的照片；取出来的是搜索、总结、关联、洞察。

| 子项目 | 类型 | 技术栈 | 规模 |
|--------|------|--------|------|
| `miniapp` | 微信小程序 | 原生 WXML/WXSS/JS | 12 页 · ~17,400 行 |
| `server` | 后端 API | NestJS 11 + TypeORM + PostgreSQL | 6 模块 · 3 实体 · ~5,900 行 |

## 核心功能

### 🎙️ 记 — 张嘴就记

- **语音/文字/图片/混合输入**：按住说话，松手完成。AI 解析 → 自动分类、提取人物/金额/日期/状态 → 确认卡片，哪里不对点哪里改
- **批量拆分**：一句话包含多人多事时（"老王浇了30平，老李贴了50平瓷砖"）自动拆分为多条记录
- **图片识别**：拍照记账单/工单，视觉模型提取文字并入档
- **快捷词**：高频内容一键记录

### 📋 看 — 让数据活起来

- 时间线浏览，按分组/标签/人物筛选
- 日历热力图 · 心情河流 · 连续记录天数
- 往日回顾（随机回忆）· 往年今日
- 数据卡片（可分享的统计图）

### 🔍 问 — 问自己的数据

- 自然语言问答："上次跟老张聊的供货那事后来怎么了" → AI 直接回答，不是翻列表
- 周报/月报 AI 自动总结

### 💰 借支台账

- 建筑工人高频刚需：借支登记、按人汇总余额、标记还款

### 📥 导入导出

- CSV 导入（可选 AI 增强：自动补标签/分组/状态）· 图片/文本批量导入
- 导出 CSV / Markdown——数据永远属于用户

### 🔒 隐私

- 隐私锁 · JWT 认证 · 数据仅本人可见

## AI 多模型工程（本项目最大亮点）

1. **多模型路由与容灾**：DeepSeek 主模型，请求失败自动降级到智谱 GLM-4-Flash——单点模型故障不影响用户记录
2. **多模态**：通义 Qwen-VL 视觉模型解析图片内容，百度短语音识别转写音频
3. **本地 AI 不依赖网络**：服务端加载 Xenova 中文 Embedding（bge-small-zh-v1.5）做语义相似度匹配，断网时优雅降级、服务不崩
4. **分组三级决策，LLM 只做兜底**：关键词词库（24 类，校准 39/39）→ 本地语义匹配 → AI 建议。关键词是唯一权威，AI 仅在无关键词命中时兜底——用确定性规则解决 LLM 归类不稳定问题
5. **成本控制**：按任务复杂度分级选模型，单次 AI 成本约 ¥0.001

## 项目状态与反思

**代码、功能、测试、真机验证（父亲 + 工友真实使用）均已完成，但未能上线。**

原因是：微信小程序商用收费需要**企业主体**（营业执照）+ 微信支付商户号 + ICP 备案，个人开发者无法开通。作为没有公司主体的个人开发者，产品卡在了商业资质门槛——**不是技术没做完，是合规资质这道门进不去**。

这本身就是重要的一课：**能上线的产品 ≠ 写完代码，商业合规是产品的一部分。**

### 这个项目我学到了什么

1. **完整的 0→1 产品闭环**：市场调研（6 方向扫描）→ 用户访谈 → PRD → UI 设计 → 前后端开发 → 测试 → 真机验证，第一次独立走完全流程
2. **AI 工程实践**：多模型路由与容灾、结构化输出、提示词工程、本地 Embedding、成本控制
3. **先验证再开发**：从上个项目（为家航）的复盘中学到 MVP 思维——用 4 周做出最小可用版本，先验证"用户是否愿意用"，而不是先写五万行代码
4. **真实用户研究**：父亲和工友是真机测试用户，验证了"张嘴就记"的真实场景与工友的借支/记工刚需
5. **工程质量意识**：单元测试驱动修复、数据校准闭环（词库 39/39）、UI 双体检、根因分析
