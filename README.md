# 活记

一个语音记录工具。按住说话，AI 把这段话整理成一条结构化记录：时间、人物、金额、状态，自动分类归档。之后可以问它："上次跟老张聊的供货后来怎么样了？"

最早是想给做建筑的父亲和工友解决记工问题——干了几天活、谁借了谁多少钱，全靠嘴记，经常扯皮。做着做着发现这玩意谁都能用：记工、记账、记会议都行。不做模板，用户说什么就记什么，AI 决定怎么结构化。

## 功能

- 语音、文字、图片三种方式记录。后端做语音识别 + AI 解析，前端弹确认卡片，解析不对的地方手动改
- 一句话里有多个人的多件事，自动拆成多条（"老王浇了30平，老李贴了50平瓷砖"拆成两条）
- 拍照记录单：通义 Qwen-VL 提取图片里的文字
- 借支台账：登记、还款、按人汇总余额，这是工友的刚需
- 智能分组：24 类关键词词库 + 本地中文 embedding 语义匹配 + AI 兜底，三级决策
- 问自己的数据：自然语言问答、周报/月报自动总结
- CSV 导入（可选 AI 补标签）、导出 CSV / Markdown
- 日历热力图、心情河流、连续记录天数、往日回顾、往年今日
- 隐私锁、JWT 认证

## 技术

- 小程序：微信原生开发，12 个页面，约 17,400 行
- 后端：NestJS 11 + TypeORM + PostgreSQL，6 个模块（records / groups / loans / ai / auth / speech），约 5,900 行

AI 接了好几家，做了容灾：

- 文本解析主力是 DeepSeek，请求失败自动切智谱 GLM-4-Flash
- 图片走通义 Qwen-VL，语音转写走百度短语音识别
- 服务端本地跑 Xenova 的 bge-small-zh-v1.5 中文 embedding 做语义匹配，断网时降级不崩

分组这块花的时间最多。LLM 归类不稳定——"火锅"能被归进"采购"，同一句话问三次答案还不一样。最后定的方案是：关键词词库是唯一权威，AI 只在没有关键词命中时兜底。词库 24 类校准到 39/39 全对，现场抽检 15/15。

## 测试

- Jest 单测 23/23（分组决策 7 例 + 存量 16 例）
- 分组回归脚本在 server/scripts/grouping/（verify-group / spot-check / reclassify-check）
- UI 体检报告在 docs/，当时查出 331 处硬编码色值之类的系统性问题

## 为什么没上线

功能、测试、真机（父亲和工友用了一周）都完成了，但没能上线。原因是微信小程序商用收费需要企业主体——个人开发者开不了微信支付商户号。没有公司，这一步就过不去。

这件事让我明白：技术做完不等于产品能上线，商业合规也是产品的一部分。做第二个项目时的教训：先验证再开发，所以这次只用了 4 周做出 MVP 就开始真机测试，没有像上一个项目那样闷头写几万行。

## 本地运行

后端需要 PostgreSQL 17，配置参考 server/.env.example（数据库和各家 AI 的 key）。然后：

```bash
cd server
npm install
npm run build
node dist/main.js    # 或双击根目录的 启动后端.bat
```

小程序用微信开发者工具打开 miniapp/ 目录，联调地址指向 http://127.0.0.1:3000/api。

## 目录

- miniapp/ — 微信小程序
- server/ — NestJS 后端
- docs/ — PRD、UI 体检报告
- design/ — 图标和品牌物料
