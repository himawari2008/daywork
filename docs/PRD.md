# 活记 — 产品需求文档

> 任何人的个人AI智能体。你记录生活，它让数据活起来。

---

## 一、产品灵魂

### 1.1 核心命题

**如果个人数据能有价值，那么记录便有了习惯。**

人不记录，不是因为懒——是因为记录只有当下的麻烦，没有未来的回报。

活记把"记录"变成"积累"。你今天说的每一句话，都在喂养一个越来越懂你的AI。三个月后，你问"上次跟老张说的那个事后来怎么了"，它告诉你。一年后，你的数据自动生成一份年度回顾，你甚至不知道自己记了这么多。

**习惯不是培养出来的，是回报驱动出来的。**

### 1.2 一句话定义

> 活记是一个**个人AI智能体**——你负责记录，它负责让数据变活。

存进去的是你说的话、你拍的照片、你觉得重要的事。取出来的是搜索、总结、关联、洞察。

### 1.3 为谁而做

**任何人。**

建筑工人记工、白领记会议、学生记笔记、自由职业记项目进度、小店主记进货——用户决定记什么，AI决定怎么结构化。

无需选择"我是谁"。打开就记。

### 1.4 与传统工具的本质区别

| | 笔记/账本工具 | 活记 |
|---|---|---|
| 记录方式 | 打开→选模板→填字段 | 说话→AI解析→确认 |
| 数据结构 | 用户预设的固定模板 | AI动态识别、自动结构化 |
| 数据用途 | 存了就存了 | AI搜索、总结、关联、预测 |
| 用户感受 | "我在记账" | "我在养一个越来越懂我的AI" |
| 产品定位 | 垂直工具 | 平台——什么都能记 |

## 三、产品原则

**原则一：不做模板、不做模式切换。**
打开就记。用户记录的内容决定数据结构，AI动态适配。没有"记工模式"、"记笔记模式"——用户只是在说话。

**原则二：语音优先，手动不缺席。**
默认语音。方言、噪音、表达不清时，可打字、填表、逐项修改。AI做完大部分工作，剩余的用户随时接管。

**原则三：每次记录必须有即时反馈。**
记完一条不只是"保存成功"。用户立刻看到：今日记录了几条、相关主题有什么、AI识别出的关键信息。每记一次，数据画像更新一次。

**原则四：自然语言查询。**
"上次跟老张吃饭说的那个事" → AI直接回答，不是翻列表。

**原则五：平台架构，零假设。**
数据模型不预设任何行业。建筑工人、白领、学生、店主——同一个产品，AI自动适配。

## 四、数据模型

### 4.1 动态结构

活记不预设字段。每条记录的结构是：

```
{
  时间:         AI识别或当前时间,
  原始内容:      用户说的话 / 打的字,
  AI摘要:        一句话概括,
  自动标签:      AI动态生成, 如["工作","装修","张三"],
  关联人物:      AI提取的人名,
  关联事件:      AI关联的历史记录,
  数值信息:      AI提取的数字(金额/数量/时长等),
  状态标签:      AI判断的状态(待办/已完成/待跟进等),
  附件:          照片/语音文件
}
```

AI每解析一条记录，自动判断需要哪些字段。不是所有记录都有"金额"，不是所有记录都有"状态"。是什么就存什么。

### 4.2 一个例子

用户说：*"下午三点跟老张在星巴克聊了供货的事，下周一之前要给他报价"*

AI解析结果：
```
时间: 2026-07-04 15:00
原始内容: 下午三点跟老张在星巴克聊了供货的事，下周一之前要给他报价
AI摘要: 与老张在星巴克讨论供货，需下周一前提供报价
自动标签: 工作, 供货, 会议
关联人物: 老张
数值信息: 截止日期 2026-07-07
状态标签: 待办
```

用户再记：*"给老张发了报价，总共三种规格，6800、9200、15000"*

AI除了解析当前记录，还会自动关联上一条"待办"，并将上一条标记为"已完成"。

## 六、AI能力

### 6.1 NLU解析引擎（核心）

每次用户记录时调用。自然语言 → 动态结构化记录。

模型：Claude Haiku，单次约 ¥0.001

### 6.2 语义搜索（V2）

自然语言 → 数据库检索 + AI回答。

模型：Claude Sonnet，单次约 ¥0.003

### 6.3 主动智能（V2）

定时规则 + AI文案生成。关联提醒、周期总结、数据画像更新。

### 6.4 语音识别

前端：微信同声传译插件（免费，普通话准确率高，方言弱）
备选：用户可手动修正识别结果

## 七、技术实现

### 7.1 架构

```
微信小程序（前端）
    │
    ├── 微信同声传译插件（语音→文字）
    │
    └── HTTP/WebSocket
            │
    NestJS API（后端）
    ├── POST /records         创建记录（含AI解析）
    ├── GET  /records         查询记录列表
    ├── GET  /records/:id     单条详情
    ├── PATCH /records/:id    修改记录
    ├── DELETE /records/:id   删除记录
    ├── GET  /stats           统计汇总
    ├── GET  /search          搜索（V2）
    └── POST /ai/parse        AI解析（内部调用）
            │
    PostgreSQL 17
    Redis 5.0（缓存 + 限流）
```

### 7.2 开发路线（4周）

| 周次 | 内容 |
|------|------|
| 第1周 | 后端骨架 + 数据库 + AI解析API（说话→结构化能跑通） |
| 第2周 | 小程序3页 + 语音交互 + 记录CRUD |
| 第3周 | 前后端联调 + 基础统计 + Bug修复 |
| 第4周 | 真机测试（作者父亲 + 工友） |

## 十、MVP不做的事

- 考勤打卡、招工找活、社区/资讯（不是平台定位）
- 人脸识别/GPS追踪（侵犯隐私）
- PC后台（用户只用手机）
- 方言语音专项优化（先用普通话MVP验证）
- AI搜索（V2）
- 职业名片/年度报告（V2）
- 团队协作/多人共享（V2）
- 任何预设模板
